Bud Agent System

A full-stack AI agent framework supporting real-time interactive sessions, scheduled automation (cron), and inter-agent communication (inbox). Agents execute tools locally (desktop) and remotely (backend), with persistent memory, workspace files, and MCP connector integration.

⚡
Interactive Sessions
Real-time Socket.IO protocol. User sends messages, LLM streams responses, tools execute on client or server with approval gating.
🕑
Cron Automation
Scheduled agent runs. Non-streaming, suspension-aware. Accumulates results, deduplicates actions within 24h windows.
📩
Inbox Messaging
Inter-agent communication. Agents can reply, escalate to user, or mark goals complete. Enables multi-agent workflows.
🔧
Tool System
17 local tools (bash, file ops, browser), 11 remote tools (memory, search, workspace), plus dynamic MCP connector tools.
🧠
Memory System
Hybrid Vespa search (70% vector + 30% BM25) with PostgreSQL fallback. Auto-injects relevant memories into system prompt.
📡
Socket.IO Protocol
Stateless event-driven architecture. Room-based routing for reconnection. JWT/cookie auth. Bidirectional streaming.

Key Design Principles

Stateless Handler
AgentHandler is instantiated fresh per Socket.IO event. All state lives in PostgreSQL (sessions, messages) and Redis (stop flags). Survives server restarts.
Unified Agent Loop
run_sync_agent_loop() in agent_context.py is shared by all three execution modes (interactive, cron, inbox). One LLM turn logic, three delivery mechanisms.
Single Active Session
Only one ACTIVE session per user at a time. Creating a new session auto-deactivates previous ones via _deactivate_user_sessions().
Session Compaction
When history exceeds 300K chars, LLM summarizes old messages. Creates new session with compaction_summary. Prevents runaway context.

Interactive Session Flow

Real-time agent execution via Socket.IO. This is the primary execution path for user-facing agent interactions.

Key Implementation Details

▶
Stop Flag Checking

During LLM streaming, the handler checks Redis for a stop flag every STOP_CHECK_INTERVAL (10 stream events). If flagged, emits agent:stopped and sets session status to IDLE. Triggered by the agent:stop event from client.

▶
Pending Tool Queue

When the LLM requests multiple tool calls in one turn, they're queued in pending_local_tools (JSONB on AgentSession). After each tool:result, the handler checks if more tools are pending. If yes, emits the next tool:request. If no, continues the LLM turn with all results.

▶
Reconnection (agent:rejoin)

Socket.IO rooms are keyed by session:{session_id}. On reconnect, client emits agent:rejoin to re-join the room. If the agent is still running (status = RUNNING or AWAITING_TOOL), events continue to flow. Session state reconstructed from DB.

Cron Execution Flow

Scheduled agent runs via Celery Beat. Non-streaming, suspension-aware for local tool execution.

Inbox Processing Flow

Inter-agent communication. One agent sends a message, the target agent processes it with specialized reply/escalate/complete tools.

PRIMARY Socket.IO

Shared: run_sync_agent_loop()

All orchestrators call this unified function in agent_context.py. It:

  • Takes an AgentRunContext with tools, prompt, LLM config, and history
  • Calls the LLM with streaming enabled
  • Processes stream events (text delta, thinking, tool calls)
  • Handles remote tool execution inline
  • Returns pending local tools for the caller to route

Agent Context Building

How the system prompt, tools, and message history are assembled before each LLM turn.

Workspace File Loading

The context builder loads 5 workspace files into the system prompt: AGENTS.md, SOUL.md, IDENTITY.md, USER.md, MEMORY.md. Files exceeding 20K characters are truncated (70% head + 20% tail kept).

Connector Tools Dynamic MCP

Discovered dynamically from MCP servers registered in the database. Each connector's tools are wrapped as FunctionTool objects with schema sanitization. Per-user approval via AgentToolPermission / AgentConnectorPreference.

Tool Approval Pipeline

How tool permissions are checked and approval is requested from the user.

Permissions stored in AgentToolPermission table. Per-user, per-tool. Levels: ALWAYS_ALLOW, NEED_APPROVAL (default for 8 tools), BLOCKED.

MCP Integration

Model Context Protocol for connecting agents to external services and APIs.

Discovery
MCP servers are registered as MCPServer records in PostgreSQL. System-managed (not per-message discovery). Loaded at context build time.
mcp_service.py: create_default_mcp_tools()
Schema Wrapping
Each MCP tool's JSON schema is sanitized for LLM compatibility. Wrapped as a FunctionTool with the MCP call as the execution handler.
Schema sanitization for edge cases
Execution
Tool calls dispatched to the MCP server via call_mcp_tool(). Results fed back to the LLM in the same turn. Per-user approval via AgentConnectorPreference.
connector_service.py
Approval Gating
Connector tools check AgentConnectorPreference for the user. If approval required, emits tool:approval_required event. Uses event-driven approval via Socket.IO.
tool_definitions.py: is_connector_tool()

Connection Setup

Endpoint
/ws/agent/ path, mounted as ASGI app on the FastAPI server.
Authentication
JWT token in headers, session cookie, or auth token in handshake. Validated on connect event.
Rooms
Clients join session:{session_id} room. Enables multi-tab and reconnection support. Events routed to room or direct SID.
Timeouts
Extended ping interval and timeout for long-running tool operations. Prevents false disconnects during bash execution.

Key DB Operations

All operations in backend/onyx/db/agent.py (~600 lines):

  • Session: create, get, list, update status, deactivate previous
  • Messages: add (user/assistant/tool/system), get history, update tool result
  • Execution: set/get execution status, check stopped flag
  • Pending tools: persist and load pending_local_tools JSONB
  • Compaction: create compacted session, mark old as COMPACTED
  • Memory: create, search by text, list for user
  • Workspace: upsert, get, list workspace files

Memory System

Persistent agent memory with hybrid search across Vespa vector store and PostgreSQL.

Workspace Files

Configuration files injected into the agent's system prompt. Customizable per-user.

FilePurposeInjection
AGENTS.mdAgent behavior instructions, capabilities, boundariesAlways loaded
SOUL.mdAgent personality, tone, communication styleAlways loaded
IDENTITY.mdAgent identity, name, role contextAlways loaded
USER.mdUser-specific context, preferences, team infoAlways loaded
MEMORY.mdStructured memory index (auto-maintained)Always loaded

Files exceeding 20K characters are smart-truncated: keep 70% from the start and 20% from the end, with a truncation marker in between. Stored in the AgentWorkspaceFile table, managed via REST API and workspace_service.py.
