# Task List Implementation Loop

Run the Ralph Wiggum loop to implement the task list. The loop exits when all the task are marked complete.

Use `/ralph-wiggum:ralph-loop` with the following prompt:

```
/ralph-wiggum:ralph-loop TASK LIST IMPLEMENTATION LOOP. PHASE 1 - ANALYSIS, every iteration: 1. Read the task list file: $ARGUMENTS 2. Identify ALL uncompleted tasks marked with unchecked checkboxes. 3. If no uncompleted tasks remain, output completion. 4. Build a dependency graph - which tasks are independent vs which depend on others. 5. Group into independent tasks that can run NOW in parallel, and blocked tasks. PHASE 2 - IMPLEMENTATION: For each batch of independent tasks, spawn parallel subagents. Use the Agent tool to launch multiple subagents concurrently, one per independent task. Use isolation worktree when parallel tasks may touch overlapping files. For dependent or sequential tasks, implement them one at a time in order. SUBAGENT PROMPT - include ALL of the following for each subagent: The exact task description from the task list. Relevant file paths and surrounding code context. Key project conventions - strict typing, no response_model, db ops only in db dirs. Instruction to return a summary of all files changed and what was done. PHASE 3 - QUALITY GATE, after each task or parallel batch. Before marking ANY task complete, verify: CODE CORRECTNESS - Read back every changed file and verify the logic is sound. Ensure no half-finished implementations, placeholder TODOs, or dead code. Check error paths at system boundaries. Verify all imports exist and are used. TYPE SAFETY - Python: full type annotations on all function signatures. TypeScript: no any types, use proper interfaces. Verify Pydantic models have correct field types. INTEGRATION CHECK - Trace how new code connects to existing callers and callees. Ensure function signatures match caller expectations. Check DB schema changes have migrations. Verify API changes reflected in both backend and frontend. TESTS AND LINT - Run relevant tests via pytest or npm test. Run linting and type checks. If tests fail, FIX before proceeding. Write at least one test for new logic paths. REGRESSION CHECK - Verify previously completed tasks still work. Fix regressions before moving on. Only after ALL quality checks pass: Update the task list file by checking off completed tasks. Commit with a clear descriptive message. RULES: Maximize parallelism. Follow CLAUDE.md strictly. Do NOT skip tasks. Do NOT mark a task done if any quality check fails. Fix subagent failures inline or retry next iteration. Prefer small focused commits. COMPLETION CHECK every iteration: Read the task list file. Count remaining uncompleted tasks. If ALL tasks are checked off, output completion. --completion-promise ALL_TASKS_COMPLETE $ARGUMENTS
```
